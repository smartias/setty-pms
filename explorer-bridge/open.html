📂 Opening in File Explorer…

Project folder: (none)

Nothing opened? The usual causes, in order:
  1. The browser is asking first. Look for an "Open SettyPMS?" / "This site wants to open an application" prompt (often behind this tab or at the top of the window). Tick "always allow" and confirm.
  2. The handler isn't installed on this computer. One-time setup, no admin rights: download SettyPMS-Explorer-Setup.cmd, run it, then click Open again. What it does ↗
  3. The handler is an old version. It is cached on this computer and never updates itself. Symptoms: "Work in the project folder" just opens File Explorer, or Test the handler below shows no dialog. Re-run the same setup file above; it replaces the handler.
  4. Claude Code isn't installed (Work in the project folder only). The Claude desktop app is not enough: install Claude Code from claude.com/claude-code and sign in once. The handler says so in a dialog when this is the cause.
  5. Company security software blocked it. On managed machines, endpoint protection can silently stop the browser from starting PowerShell. IT can allow the handler (details in the PMS Admin Console guide).

🧪 Test the handler — a dialog with the handler version and what it found should appear within a few seconds. No dialog at all means cause 2, 3 or 5. The handler also writes %LOCALAPPDATA%\SettyPMS\last-run.log on every click.
